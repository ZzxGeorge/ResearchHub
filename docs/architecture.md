# 架构与关键决策

## ADR 001 — 单用户、本地优先
React + Vite 静态前端由 FastAPI 同源提供；开发时 Vite 仅代理 /api。默认仅绑定 127.0.0.1，不提供 CORS 通配访问。写请求校验 Origin 和本地 Host，避免外站向本机写入。没有登录、遥测、外部 API 或云部署。

## ADR 002 — 正文与索引职责
六类知识共用 nodes 实体，类别专属元数据通过 Pydantic 校验并保存 JSON。稳定 UUID 作为跨模块引用。正文只存放在模块目录中的不可变 Markdown 版本；SQLite 保存当前版本路径及版本历史。全文缓存可从 Markdown 重建，不作为正文来源。

写入顺序：workspace 跨进程文件锁 → 检查乐观版本 → 原子写新 Markdown → 更新节点、历史、搜索索引 → 提交 SQLite。失败时旧指针不变，最多留下未引用文件；不自动清理这些文件。读取、备份与导入也使用同一锁，单用户负载下优先一致性。导入所有节点、关系、收据在一个事务提交。附件同样使用不可变 UUID 文件名。

## ADR 003 — 可演进结构
SQLAlchemy 实体、服务、API、Pydantic 协议分层；Alembic 迁移。统一知识节点允许未来增加实验/RAG 适配器，不引入向量数据库。数学与算法正文可独立复用，通过有向边连接。related_to 和 compares_with 是对称边，其余边有方向，详情中同时显示入边和出边。

## ADR 004 — 搜索与数据独立
SQLite FTS5 unicode61 处理英文词项；中文和混合查询使用归一化子串回退，保证无需独立分词服务即可检索中文。索引在写入/导入/软删除时同步维护，并支持重建。备份使用 SQLite backup API 一致性快照，记录所有文件的 SHA256；恢复只允许进入不存在的新工作空间，不覆盖现有资料。

## 开发阶段
1. 基础实体、迁移、CRUD、附件、Markdown、导航与真实统计。
2. v1 协议、预览、手动匹配、事务导入、搜索。
3. SM-2 复习、有限图谱、想法看板、完整备份与独立恢复。
4. 自动化验收、浏览器检查、文档和启动脚本。实际验证状态见 DEVELOPMENT_STATUS.md。
